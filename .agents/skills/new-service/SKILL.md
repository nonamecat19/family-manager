# new-service

Reference implementation to copy: `services/auth`.

## Layout

```
services/<name>/
  go.mod                     module github.com/nnc/family-manager/services/<name>
  cmd/server/main.go         wiring only — config, deps, listen :8080 (Connect) / :9090 (gRPC)
  internal/config/config.go  viper, env-prefixed, no defaults for secrets
  internal/grpc/server.go    Connect handler: proto types <-> handler types
  internal/events/           JetStream publishers + durable consumers (via libs/go/events)
  internal/handler/          business logic, no proto types, no SQL strings
  internal/db/
    migrations/000001_init.up.sql
    queries/<entity>.sql
  db/                        GENERATED by sqlc — never hand-edited
  sqlc.yaml
  .air.toml
  .env.example               committed; .env never
  Makefile                   proto/sqlc/run/dev/migrate targets
```

Layer rule: `handler` never imports proto, `grpc` never contains business logic, `db` is
generated. Shared concerns (auth middleware, logger, pg pool, event bus) come from
`libs/go/*` — do not re-implement per service.

## Steps (sequential — one agent through step 5)

1. `mkdir -p services/<name>/{cmd/server,internal/{config,grpc,handler,db/{migrations,queries}}}`
2. `cd services/<name> && go mod init github.com/nnc/family-manager/services/<name>`
3. Copy and adapt from `services/auth`: `sqlc.yaml`, `.air.toml`, `Makefile`, `.env.example`,
   `internal/config/config.go`.
4. Contract: create `libs/proto/<name>/v1/<name>.proto` (plus `events.proto` if the service
   publishes). Package `<name>.v1`, **no `go_package`** — buf managed mode sets it. The
   directory name must equal the service directory name; that is how the graph assigns
   ownership. Then `just proto` and implement the generated
   `<name>v1connect.<Name>ServiceHandler`, mounted on `:8080`.
5. Register the module in `go.work`:
   ```
   use ./services/<name>
   ```
   then `go work sync`.
6. Wire infra: add any new backing store to `docker-compose.yml`, and the service itself to
   `docker-compose.services.yml`; put its DSN in `.env.example`.
7. `just graph` — **the service, its contract, its rpcs and its tables must appear as nodes.**
   If they do not, the scaffold is wrong (usually a missing `go.work` entry or a `.proto` in
   the wrong place). Check `jq '.dropped' docs/graph/graph.json` is empty.

## Then fan out (parallel, disjoint files)

- migrations + `queries/*.sql` + `just sqlc <name>`
- gRPC handlers + unit tests
- config/wiring + `.env.example` completion

## Done when

```sh
just check-go        # builds, vets, tests across the workspace
just graph           # new nodes present, dropped list empty
just impact service:<name>    # blast radius as expected (should be small for a new service)
```

Human gate on the first migration before it is applied anywhere shared.
