# ADR 0005 — Auth: short-lived ES256 JWT + rotating refresh tokens, verified via JWKS

- Status: accepted
- Date: 2026-08-06

## Context

Every service needs to know who is calling, and every app needs a session that survives app
restarts on a device we do not control. Mobile clients cannot hold a shared signing secret, and
services must not call the auth service on every request.

## Decision

**`services/auth` is the only issuer.** It owns `users`, `refresh_tokens`, and the signing key.

- **Access token**: JWT, **ES256** (asymmetric), TTL **15 min**. Claims: `sub` (user id), `iat`,
  `exp`, `jti`, `fam` (family id), `roles`. Sent as `Authorization: Bearer <jwt>` on Connect and
  gRPC calls.
- **Refresh token**: opaque 256-bit random string, stored **hashed** (SHA-256) in
  `refresh_tokens` with `user_id`, `expires_at` (30 days), `revoked_at`, `replaced_by`, and a
  device label. `Refresh` rotates: the presented token is revoked and a new pair is issued.
  **Reuse of an already-rotated token revokes the whole chain** — the standard stolen-token
  signal.
- **Verification**: `services/auth` publishes its public keys at `/.well-known/jwks.json`.
  `libs/go/auth` provides a Connect interceptor that fetches JWKS once, caches by `kid`,
  refreshes on unknown `kid`, and validates signature + `exp` + issuer **locally**. No service
  calls the auth service per request.
- **Key rotation**: two keys live in JWKS at once. A new key is published, becomes the signer
  after one access-token TTL, and the old key is removed after another. Rotation needs no
  service restarts.
- **Client**: `packages/auth` stores both tokens in **expo-secure-store** (Keychain/Keystore),
  refreshes on 401 through a single-flight mutex, and clears both on logout. Tokens never touch
  AsyncStorage, Zustand, or a log line.

## Alternatives

- **HS256 with a shared secret** — every service would hold the signing key; one compromised
  service could mint tokens for all of them.
- **Opaque tokens with per-request introspection** — auth service becomes a hard dependency on
  every request and a single point of failure.
- **Sessions in Postgres** — same coupling, plus a DB round-trip per request across services.

## Consequences

- Revocation is not instant: a stolen access token stays valid up to 15 minutes. Accepted — the
  refresh chain is revocable immediately, which is where real theft is detectable.
- `libs/go/auth` becomes load-bearing for every service; changes there go through the human gate
  (`just impact golib:auth`).
- The JWKS endpoint must be reachable from every service; it is served over plain HTTP inside the
  compose network and over TLS via Caddy externally.
- Password hashing is **argon2id** with per-user salt, in `services/auth` only. No other service
  ever sees a credential.
- Tests: `libs/go/auth` ships a test helper that mints tokens against a throwaway key, so other
  services never need a running auth service to test authorized paths.
